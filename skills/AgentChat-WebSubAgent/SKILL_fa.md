# راهنمای مهارت AgentChat-WebSubAgent

> **اصل اصلی**: مغز Claude Code → جستجوی Kimi → (پیچیده؟ استدلال Gemini) → ترکیب Claude → بازبینی ChatGPT → تعمیر Claude  
> **لایه Provider**: `AgentChat-OneWeb`، بدون تکرار کد  
> **استراتژی امنیتی**: هرگز Chrome کاربر را نبندید

## ⚠️ قوانین اجباری — فراخوانی یعنی اجرا

**هنگامی که این skill فراخوانی می‌شود، باید مراحل 1→6 را به ترتیب اجرا کنید. مرحله 2 و 5 بدون قید و شرط اجرا می‌شوند، مرحله 3 بسته به پیچیدگی تعیین می‌شود. ممنوع است از هر مرحله‌ای بپرید، ممنوع است فقط جریان کار را توضیح دهید بدون اجرا.**

محدودیت‌های کلیدی:
- ❌ ممنوع: بعد از خواندن SKILL.md خط لوله را توصیف کنید، تقسیم نقش‌ها را توضیح دهید، معماری را تحلیل کنید — اما `node index.js` را اجرا نکنید
- ❌ ممنوع: با این توجیه که "وظیفه خیلی ساده است/کاملاً محلی است/نیاز به جستجو ندارد" از مرحله 2 (`--search`) بپرید
- ❌ ممنوع: با این توجیه که "خروجی ساده است/نیاز به بازبینی ندارد" از مرحله 5 (`--review`) بپرید
- ❌ ممنوع: خواندن فایل محلی، تحلیل کد، یا دانش خود Claude را جایگزین فراخوانی `node index.js` کنید
- ✅ الزامی: مرحله 2 و 5 **بدون قید و شرط اجرا شوند**. قضاوت پیچیدگی فقط تعیین می‌کند که آیا مرحله 3 (استدلال Gemini) رد شود یا نه
- ✅ الزامی: هر مرحله خروجی JSON قابل تأیید `node index.js` تولید کند، تنها پس از بازگشت نتایج مجاز به اضافه کردن تفسیر خود هستید

### رسید اجرایی (receipt) — معیار اجرا همین است، نه توصیف

هر بار اجرای `node index.js --search/--reason/--review` در خروجی JSON شامل فیلد `receipt` تولید شده توسط ماشین است
(همچنین stderr یک خط `[receipt] AGENTCHAT_RUN {...}` چاپ می‌کند):

```json
"receipt": { "run_id": "ac-xxxxxxxxxxxx", "skill": "AgentChat-WebSubAgent", "mode": "search", "exit": 0, "provider_used": "kimi", ... }
```

- **گزارش نهایی باید run_id هر اجرا را به صورت مرحله‌ای فهرست کند** (یک مورد برای مرحله 2؛ یک مورد برای مرحله 3 اگر اجرا شد؛ یک مورد برای مرحله 5).
- فقدان run_id یک مرحله = آن مرحله اجرا نشده = تخلف، باید دوباره اجرا کنید.
- run_id به صورت تصادفی تولید می‌شود و در `skills/AgentChat-WebSubAgent/data/receipts.jsonl` ذخیره می‌شود، کاربر می‌تواند با `grep <run_id>` بررسی کند، ساختن جعلی قابل عبور از بررسی نیست.
- **اجرای شکست‌خورده (exit≠0) نیز receipt دارد**: رسید شکست را نقل کنید، دلیل降级/شکست را توضیح دهید، سپس مجاز به ادامه آن مرحله با توانایی مدل خود هستید، و باید صریحاً ذکر کنید "web AI در این مرحله مشارکت نداشت".

**اصل ضد دور زدن**: اگر یک مرحله "به نظر نمی‌رسد نیاز به web AI داشته باشد"، روش صحیح این است که همچنان از طریق `node index.js` یافته‌های محلی را برای تأیید/تکمیل/بررسی متقاطع به web AI ارسال کنید — نه اینکه آن مرحله را رد کنید. prompt جستجوی مرحله 2 و محتوای بازبینی مرحله 5 باید شامل نتایج تحلیلی محلی Claude باشد، تا web AI تأیید ثانویه انجام دهد.

**چک‌لیست خودسنجی** (Claude Code باید قبل از خروجی نهایی تأیید کند همه تکمیل شده‌اند):
- [ ] مرحله 2: `node index.js --search` اجرا شد، JSON بازگشت؟ receipt.run_id = ______
- [ ] مرحله 3: (وقتی پیچیده است) `node index.js --reason` اجرا شد؟ receipt.run_id = ______ (وقتی ساده است) دلیل رد شدن به صراحت ثبت شد؟
- [ ] مرحله 5: `node index.js --review` اجرا شد، JSON بازگشت؟ receipt.run_id = ______
- [ ] مرحله 6: نظرات بازبینی مورد به مورد پردازش شدند؟
- [ ] گزارش نهایی همه run_idهای فوق را فهرست کرده است؟

استثنا: `--smoke`، `--doctor`، یا وقتی کاربر صریحاً درخواست کند "فقط محیط را بررسی کن، ارسال نکن".

## معماری

```
درخواست کاربر → [1.برنامه‌ریزی Claude] → [2.جستجوی Kimi] →{پیچیده؟}→ [3.استدلال Gemini] → [4.ترکیب Claude] → [5.بازبینی ChatGPT] → [6.تعمیر Claude] → خروجی نهایی
                                              └── ساده: رد شود ──┘
```

خط لوله سریال + شاخه شرطی. Claude Code در تمام طول به عنوان مغز عمل می‌کند، فقط در مرحله 2/3/5 از طریق index.js OneWeb را فراخوانی می‌کند.

## قضاوت پیچیدگی (مرحله 1)

**فقط تعیین می‌کند که آیا مرحله 3 (استدلال Gemini) اجرا شود یا نه. بر اجرای اجباری مرحله 2 و 5 تأثیری ندارد.**

**در صورت عدم اطمینان تمایل به قضاوت "پیچیده" داشته باشید**.

**پیچیده** (فعال‌سازی مرحله 3، رضایت ≥2 مورد):
- نیاز به ترکیب چندین منبع اطلاعاتی برای رسیدن به نتیجه
- شامل استدلال منطقی چند مرحله‌ای یا استنتاج ریاضی
- دارای تصمیمات معماری/طراحی غیر بدیهی، یا نیاز به کد چند فایلی
- دامنه مسئله نیاز به تخصص حوزه دارد
- کاربر درخواست "تحلیل عمیق" یا "راه حل جامع" کرده است

**ساده** (رد شدن مرحله 3، اما مرحله 2 و 5 همچنان باید اجرا شوند):
- پرس‌وجوی تک‌واقعیت، کد شهودی ≤50 خط، کارهای مکانیکی مانند تبدیل فرمت و غیره

## جریان عملیات

### مرحله 1: برنامه‌ریزی و توزیع

1. درک نیاز کاربر، مرور سریع فایل‌های محلی مرتبط
2. قضاوت پیچیدگی (فقط تعیین می‌کند که آیا مرحله 3 اجرا شود)
3. **نوشتن prompt جستجوی ترکیبی** — باید شامل:
   - نیاز اصلی کاربر
   - خلاصه تحلیل محلی انجام‌شده توسط Claude (محتوای فایل، ساختار پروژه و سایر یافته‌ها)
   - زمینه حوزه یا آخرین پیشرفت‌هایی که نیاز به تکمیل/تأیید توسط web AI دارد
   - **حتی اگر مسئله ظاهراً کاملاً محلی است، باید prompt جستجو ساخته شود** — حداقل از Kimi بخواهید یافته‌های محلی را تأیید کند، آخرین تحولات حوزه را تکمیل کند، یا قضاوت Claude را بررسی متقاطع کند
4. گزارش به کاربر: پیچیدگی + پرس‌وجوی جستجو + خروجی مورد انتظار

### مرحله 2: جستجوی آنلاین (بدون قید و شرط اجرا)

⚠️ **صرف نظر از نوع وظیفه، این مرحله قابل رد شدن نیست.** حتی اگر مسئله 100% درک فایل محلی است، باید جستجو اجرا شود — ارزش در تکمیل زمینه حوزه، تأیید یافته‌های محلی، کشف آخرین تحولاتی که در README وجود ندارد است.

```bash
node skills/AgentChat-WebSubAgent/index.js --search "prompt جستجوی ترکیبی"
```

خروجی JSON است. فیلد `response` همان نتیجه جستجوی کامل Kimi است. Claude Code پس از مطالعه کامل حقایق کلیدی را استخراج می‌کند.

Fallback: Kimi → Qwen

### مرحله 3: استدلال عمیق (فقط وظایف پیچیده)

خلاصه جستجو + نیاز اصلی را به یک prompt استدلال مونتاژ کنید. فقط اطلاعات کلیدی را خلاصه کنید، متن کامل خام را نچسبانید.

```bash
node skills/AgentChat-WebSubAgent/index.js --reason "نیاز اصلی: ... خلاصه جستجو: ... لطفاً از [زاویه] تحلیل عمیق کنید، مستقیماً استدلال کامل ارائه دهید. نیازی به جستجوی منابع جدید نیست." --timeout=300000
```

Fallback: Gemini → ChatGPT → Claude

### مرحله 4: تولید اصلی

حقایق جستجو + نتیجه استدلال (در صورت وجود) + نیاز اصلی را جمع‌بندی کرده، محصول نهایی (کد/سند/گزارش) را تولید کنید. خودارزیابی: آیا همه حقایق جستجو گنجانده شده‌اند؟ آیا نتیجه استدلال جذب شده است؟ آیا نکات نیاز به طور کامل پوشش داده شده است؟

### مرحله 5: بازبینی متقاطع (بدون قید و شرط اجرا)

⚠️ **صرف نظر از نوع وظیفه، این مرحله قابل رد شدن نیست.** خروجی مرحله 4 را به طور کامل به ChatGPT ارسال کنید. ابعاد بازبینی: درستی، امنیت، عملکرد، قابلیت نگهداری.

حتی اگر خروجی "خیلی ساده" است، ارزش بازبینی در این است: کشف خطاهایی که Claude ممکن است نادیده گرفته باشد، تأیید دقت حقایق، بررسی سازگاری منطقی. بازبینی خروجی ساده ممکن است سریع باشد ("بدون مشکل" نیز یک نتیجه معتبر است)، اما باید اجرا شود.

```bash
node skills/AgentChat-WebSubAgent/index.js --review "نیاز اصلی: ... خروجی تحت بازبینی: ... لطفاً از درستی، امنیت، عملکرد، قابلیت نگهداری مورد به مورد بازبینی کنید، مشکلات را فهرست کرده و پیشنهادات اصلاحی بدهید. طرح را بازنویسی نکنید."
```

Fallback: ChatGPT → Claude → Qwen

پس از دریافت نظرات بازبینی، هر کدام را ارزیابی کنید: منطقی است → تعمیر مرحله 6 / کاربردی نیست → دلیل را ثبت کنید / نیاز به شفاف‌سازی دارد → علامت‌گذاری کنید.

### مرحله 6: تعمیر و خروجی

نظرات بازبینی را مورد به مورد اعمال کرده، فایل نهایی را خروجی دهید. گزارش به کاربر: خلاصه مراحل، دلیل قضاوت پیچیدگی، وضعیت پردازش نظرات بازبینی، موقعیت خروجی.

## 📐 مشخصات قالب‌بندی خروجی — فرمت اجباری پاسخ نهایی

موضوع محدودیت **متن نهایی نوشته شده توسط Claude Code** است؛ خروجی خام worker، بلوک‌های کد، diff، جدول‌ها و خطوط receipt مشمول نیستند.

1. **نتیجه‌گیری اول**: پاراگراف اول ≤۵۰ کلمه حاوی نتیجه اصلی (TL;DR)، مستقیماً به خواسته بنیادی کاربر پاسخ دهد، بدون تعارف، بدون مقدمه‌چینی روش‌شناختی.
2. **سطح‌بندی عنوان‌ها**: ماژول‌های اصلی با `##`، دیدگاه‌های فرعی با `###`، عنوان سطح یک `#` ممنوع است. ابعاد را در ۳–۵ بلوک منطقی دسته‌بندی کنید (مثل: پیشینه/وضعیت فعلی/تحلیل/نتیجه)، ممنوع است به ترتیب بازیابی به سبک گزارش روزنامه‌ای بنویسید.
3. **کانون بصری**: داده‌ها، زمان‌ها، نام‌های خاص، استدلال‌های کلیدی را با `**پررنگ**` علامت‌گذاری کنید؛ پررنگ فقط برای هدایت کانون توجه، حداکثر ۲ مورد در هر پاراگراف طبیعی.
4. **انضباط لیست**: فقط لیست نامرتب تک‌سطحی `*` مجاز است، هرگونه لیست تودرتوی چندسطحی ممنوع است (برای اطمینان از تجربه خواندن در ترمینال/جعبه چت).
5. **تراکم متن**: پاراگراف‌های روایی طبیعی ≤۳ جمله، شاخه منطقی جدید باید با خط جدید جدا شود؛ ممنوع است از جملات انتقالی بدون محتوای ماهوی مانند "در مجموع"، "بر اساس نتایج جستجوی فوق"، "به عنوان یک هوش مصنوعی" استفاده کنید.
6. **جداسازی اطلاعات**: هنگام نقل قطعات متن اصلی web AI یا لینک‌های خارجی، باید در بلوک نقل قول `>` قرار گیرند و منبع provider مشخص شود، به دقت از تحلیل خودتان جدا شوند.
7. **بند معافیت (اولویت بالاتر از بندهای ۱–۶)**:
   * خط `[receipt] AGENTCHAT_RUN {...}` (یا فهرست run_id هر مرحله) باید عیناً در انتهای پاسخ در بلوک کد حفظ شود، ممنوع است بازنویسی، پررنگ یا حذف شود — تابع بند اجباری §2.
   * افشای降级/شکست (مثل "N نقش降级"، "web AI در این پاسخ مشارکت نداشت") جزو شفافیت فرآیند است، جمله انتقالی اضافی محسوب نمی‌شود، نباید حذف شود.
   * بلوک‌های کد، diff، جدول‌ها مشمول محدودیت طول پاراگراف و سطح لیست نیستند.

## مرجع سریع CLI

```bash
node skills/AgentChat-WebSubAgent/index.js --search "query"     # جستجوی Kimi
node skills/AgentChat-WebSubAgent/index.js --reason "prompt"    # استدلال Gemini
node skills/AgentChat-WebSubAgent/index.js --review "content"   # بازبینی ChatGPT
node skills/AgentChat-WebSubAgent/index.js --smoke | --doctor   # بررسی محیط
```

| Flag | توضیح |
|------|------|
| `--search/--reason/--review` | حالت مرحله (یکی از سه تا را انتخاب کنید) |
| `--provider=X` | جایگزینی provider پیش‌فرض |
| `--timeout=N` | timeout بر حسب ms (پیش‌فرض 180000) |
